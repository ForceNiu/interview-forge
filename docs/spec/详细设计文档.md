- **目的**：把 TDD 中的架构决策落到「每个接口长什么样、每个函数怎么走」的颗粒度，使任何人读此文档即可还原代码，或据此补测试 / 改 bug。
- **范围**：
  - 覆盖：全部 API Route Handler、Server Actions、核心 lib 模块、关键前端组件接口、跨切面关注点。
  - 不覆盖：逐行代码、UI（用户界面）像素级样式、第三方依赖内部实现。
- **非目标**：不重复需求文档的功能描述，也不重复 TDD 的决策理由。

## 3. API 契约详表

> 通用约定：请求/响应均为 `application/json`（SSE 接口除外）；错误统一返回 `{ error: string }` + 对应 HTTP 状态码。

### 3.1 AI 出题相关接口

#### POST `/api/ai/setup-key`
设置用户自备的 DeepSeek API Key（存浏览器 Cookie，服务端不持久化明文）。
- **Request**：`{ apiKey: string }`
- **处理**：`encryptApiKey(apiKey)` → 写入 Cookie `ai_key`
  - `httpOnly: true`（JS 无法读，防 XSS（跨站脚本））
  - `secure: process.env.NODE_ENV === "production"`（仅 HTTPS）
  - `sameSite: "strict"`（防 CSRF（跨站请求伪造））
  - `maxAge: 30 * 24 * 60 * 60`（30 天），`path: "/"`
- **Response**：`200 { ok: true }` / `400 { error: "请提供 API Key" }` / `500`

#### POST `/api/ai/test`
连通性自检（前端「测试连接」按钮调用）。
- **Request**：无 body
- **处理**：`createLLM()` → `llm.invoke("请回复'连接成功'")`
- **Response**：`200 { ok: true, message: string }` / `500 { error }`（Key 缺失或网络失败）

#### POST `/api/ai/generate`（SSE 流式）
AI 出题主入口，实时推送阶段进度。
- **Request**：`{ resume: string, jd?: string }`
- **Response**：`Content-Type: text/event-stream`，逐行 `data: {json}\n\n`
- **事件相位（phase）顺序**：
  1. `analyzeResume`（done）→ 带 `analysis`
  2. `routeCandidate`（done）→ 带 `routing`
  3. `planStrategy`（done）→ 带 `strategy`
  4. `generateQuestions`（done / partial）→ 带 `questions`、`failedDomains`
  5. `refine`（running/done，仅在不达标重出时出现）→ 带 `round`、`summary`
  6. `done`（终态）→ 带最终 `questions`、`failedDomains`
  7. `error`（异常）→ 带 `error`
- **收尾**：流结束后 `recordGenerationRun` 写库（失败不影响已推送的 done）

#### POST `/api/ai/workflow-test`
非流式跑完整图，用于自测/调试（返回全量结果 + 写库）。
- **Request**：`{ resume: string, jd?: string }`
- **Response（200）**：
  ```json
  {
    "ok": true, "runId": "run_...",
    "analysis": {...}, "routing": {...}, "strategy": {...},
    "questions": [...], "failedDomains": [...],
    "round": 0, "callFailedDomains": [...], "logs": [...]
  }
  ```
- 与 `generate` 区别：用 `graph.invoke`（一次性返回）而非 `graph.stream`（流式）；其余链路完全一致。

#### GET `/api/ai/graph-order` ⚠️ 概念演示，非业务功能
最小 LangGraph 演示（nodeA→nodeB→nodeC），仅用于证明「状态在节点间自动流转、无需手动传递」。返回 `{ "执行顺序": [...], "greeting最终值": "..." }`。**不计入任何功能需求**，面试讲述时明确它是教学示例。

### 3.2 题库相关接口

#### GET `/api/questions`
题目列表（供首页/收藏页数据拉取）。
- **Query**：`?favorite=true` 时仅返回收藏题，否则全量
- **处理**：`prisma.question.findMany({ where, orderBy: { updatedAt: "desc" }, select: { id, title, difficulty, source, favorite, updatedAt } })`
- **Response**：`200 Question[]`

#### PATCH `/api/questions/[id]/favorite`
切换收藏状态（toggle 取反）。
- **Request**：路径参数 `id`
- **处理**：`findUnique` 不存在 → `404`；否则 `update({ data: { favorite: !current.favorite } })`
- **Response**：`200 updated` / `404 { error: "题目不存在" }`

#### POST `/api/ai/save-questions`
将 AI 生成题目写入题库。
- **Request**：`{ questions: QuestionInput[] }`，`QuestionInput = { title, content, difficulty, tags: string[] }`
- **处理**（逐题）：
  1. 标签复用：`tags.map` 并行 `findUnique`，命中复用、未命中 `create`（默认色 `#6366f1`）
  2. `question.create({ title, content, difficulty: clamp(1..5), source: "ai", isAiGenerated: true, userId: user.id /* prisma.user.findFirst()/upsert 动态取，非硬编码 */, tags: { create: [{ tagId }] } })`
  3. `revalidatePath("/")`
- **Response**：`200 { ok: true, savedCount }` / `400 { error: "没有可保存的题目" }` / `500`

### 3.3 Server Actions（服务端动作）

> 返回值统一用 state 对象，前端经 `useActionState` 消费。

| Action | 签名 | 校验 | 副作用 | 返回 |
|--------|------|------|--------|------|
| `createQuestion` | `(prevState, formData) => state` | `questionSchema` | `prisma.question.create`（source:"", isAiGenerated:false, userId: user.id（动态取））→ `revalidatePath("/")` | `{ error, fieldErrors?, ok? }` |
| `updateQuestion` | `(id, prevState, formData) => state`（id 由 `.bind(null,id)` 预设） | 同上 | `prisma.question.update` → revalidate `/` + `/questions/${id}` | 同上 |
| `deleteQuestion` | `(id, prevState) => state` | 无（无表单） | `prisma.question.delete` → revalidate `/` | `{ error, ok? }` |
| `createTag` | `(prevState, formData) => state` | 手写（name 非空 + 去重） | `prisma.tag.create` → revalidate `/tags` + `/` | `{ error, ok? }` |
| `deleteTag` | `(id, prevState) => state` | 无 | `prisma.tag.delete` → revalidate `/tags` + `/` | `{ error, ok? }` |

- **字段级错误**：Zod 失败 → `formatZodError` 转 `{ 字段: 信息[] }`，前端按字段标红。
- **非字段错误**：数据库异常 → `{ error: "数据库写入失败" }`。

## 4. 数据模型与 Prisma 查询模式

### 4.1 单例（src/lib/prisma.ts）
```ts
const globalForPrisma = globalThis as { prisma?: PrismaClient };
export const prisma = globalForPrisma.prisma ?? new PrismaClient();
if (process.env.NODE_ENV !== "production") globalForPrisma.prisma = prisma;
```
作用：开发热重载时复用同一连接，避免连接数耗尽。

### 4.2 嵌套 include 模式（核心陷阱）
题目与标签是多对多，中间表 `QuestionTag` 含 `tagId`。查标签名必须两层嵌套：
```ts
prisma.question.findUnique({
  where: { id },
  include: { tags: { include: { tag: true } } }, // 只写 tags:true 只能拿到中间表，拿不到标签名
});
```
`SearchableQuestions` 用 `Prisma.QuestionGetPayload<{ include: {...} }>` 类型对齐。

### 4.3 事务级联删除（FR-1.3）
删除题目前先删中间表再删题目（`$transaction`），避免外键残留。当前 `deleteQuestion` Action 直接 `prisma.question.delete`（依赖 `onDelete: Cascade` 级联）；文档标记此为「依赖 schema 级联」，若未来关级联需补事务。

### 4.4 标签复用（upsert 等价）
`save-questions` 对每标签 `findUnique` → 命中返回、未命中 `create`，避免重复标签 `@unique` 冲突。

## 5. 核心逻辑伪代码

### 5.1 AI 工作流 5 节点（src/lib/ai/workflow.ts）
```
State: { resume, jd, analysis, strategy, questions, failedDomains,
         callFailedDomains, logs, runId, generationDone, round,
         refineDomains, routing }

START → analyzeResume → routeCandidate → planStrategy
      → generateQuestions → validateQuestions
      →[shouldRefine]→ refine: generateQuestions  (回环)
                   → end: END

analyzeResume:  LLM(简历+JD) → JSON → analysis{ skills, overallLevel,
              skillCategoryMap, blindSpots }
routeCandidate: computeRouting(analysis) → routing（零 LLM 调用）
planStrategy:   LLM(analysis + routingHint) → strategy.domains[]
generateQuestions: mapWithConcurrency(domains, 5, generateForDomain) → questions
validateQuestions: 对每题 validateQuestionSemantics → 不达标域集合
shouldRefine: failed.length>0 且 round<=MAX_REFINE_ROUNDS(2) ? refine : end
```
常量：`MAX_ATTEMPTS=3`、`NODE_TIMEOUT_MS=300000`、`MAX_REFINE_ROUNDS=2`。

### 5.2 确定性路由 computeRouting（零 LLM）
```ts
function computeRouting(a: ResumeAnalysis): RoutingDecision {
  const hay = `${a.primaryStack} ${a.skills.join(" ")}`.toLowerCase();
  const hasBackend = BACKEND_KEYWORDS.some(k => hay.includes(k)); // 见 §5 末列表
  const targetRole = hasBackend ? "fullstack" : "frontend";
  const baseBias = { junior:{c:.75,d:.25}, mid:{c:.50,d:.50},
                     senior:{c:.29,d:.71}, staff:{c:.20,d:.80} }[a.overallLevel];
  const hasBlindSpots = a.blindSpots.length > 0;
  return { level, targetRole, hasBlindSpots, bias:{ concept:baseBias.c, deepDive:baseBias.d } };
}
```
为何不用 LLM：输入已是结构化对象、需同输入必同输出（可复现）、省 token（令牌）、防分类漂移/幻觉。

### 5.3 并发扇出（mapWithConcurrency 限 5 路）+ 域级重试
- 各域 `generateForDomain` 互相独立，主流程用 `mapWithConcurrency(limit=5)` 限 5 路并发调用 LLM（扇出 fan-out）。
- **并发安全**：每域写自己的 `localLogs` 便签本，跑完由主流程按固定顺序合并，避免共享 `logs` 竞态。
- **域级重试**（不交框架）：循环内对单域单次调用重试 `MAX_ATTEMPTS` 次；`withTimeout` 超时即 abort（中止）重试；成功域不被失败域连坐。最终失败域进 `callFailedDomains`（不参与精炼）。
- 实测：5 路并发约 3.8x 提速、零 429（多次实测，并发额度已非瓶颈）。

### 5.4 确定性语义校验 validateQuestionSemantics（硬门禁，不靠 LLM 评委）
对每题返回 `issues[]`，命中任一条即不达标：
1. 难度非 1–5 整数
2. 内容 `< 30` 字（`MIN_CONTENT_LEN`）
3. 标签为空数组
4. 标题+内容不含开放式关键词（为什么/如何/说说/怎么/区别/对比/解释/设计/什么/哪些/怎样）
5. 与候选人技能/技术栈无关键词重叠（相关性兜底）

### 5.5 精炼环收敛证明
- 第 N 轮校验不达标域 → 回 ④ 只重出这些域（好域保留），并注入「上一版为何不达标」提示。
- 终止条件：`failed.length === 0` 或 `round > MAX_REFINE_ROUNDS(2)`。
- 永不达标时第 3 轮停止，剩余失败域记入 `failedDomains` 返回，不卡死、不超 Vercel 300s（秒）超时。

### 5.6 Key 加解密（src/lib/crypto.ts + client.ts）
```
加密: AES-256-GCM, key=Buffer.from(API_KEY_ENCRYPTION_SECRET,"hex")(须 32 字节/64 hex)
      返回 `iv:authTag:ciphertext`（均 hex）
解密: 拆分三段 → decipher → 失败(篡改/过期)返回 null
获取: Cookie 有 ai_key → decrypt，成功即用；解密失败直接 null（不回退 .env）
      Cookie 无 → 回退 process.env.DEEPSEEK_API_KEY
创建: 自写 DeepSeekLLM（src/lib/ai/client.ts，Node http/https 经代理隧道直连，规避 Next 内 undici fetch 挂死）
      model:"deepseek-v4-flash", temperature:0.7, baseURL:"https://api.deepseek.com"
```

## 7. 跨切面关注点

### 7.1 安全
- API Key：仅存 httpOnly+strict Cookie 或 `.env`（服务端），永不到前端 JS。
- 写操作：所有写经 Zod / 手写校验，绕过客户端直接 POST 仍被服务端拦截（最后一道防线）。
- `.env` 不进 git（`.gitignore`）。

### 7.2 可观测性（L1–L4）
- **L1** `console.log`（服务端终端实时）
- **L2** `state.logs` 数组（随工作流流转，可随接口返回）
- **L3** 页面 SSE 进度条 + 琥珀色失败条
- **L4** `GenerationRun` 表（每次运行一条，`recordGenerationRun` 异常吞掉不阻塞主流程）

### 7.3 错误处理
- LLM 调用：超时 abort + 域级重试 3 次；整体 try/catch 推 `error` 事件。
- 写库（L4）：try/catch 吞异常，仅 `console.error`，不影响接口返回。
- 题目级：畸形 JSON → Zod 抛错 → 域级重试；仍失败 → 该域进 `callFailedDomains`。

### 7.4 并发
- 出题并行扇出 + `localLogs` 隔离（§5.3）。
- 前端搜索为纯客户端 `filter`，无并发问题。

## 8. 已知约束与权衡（诚实边界）

| 项 | 现状 | 影响 |
|----|------|------|
| 多用户 | `userId` 由 `prisma.user.findFirst()`/`upsert` 动态取（非硬编码），无 Auth（认证） | 当前为单人工具；多用户需接入 session（会话） |
| CI 闸门 | type-check + test + build 三道闸门 | `build` 由 Vercel 代执行，CI 不覆盖构建错误 |
| 并行提速 | 5 路并发实测约 3.8x 提速、零 429 | 架构正确无害，提速依赖上游额度 |
| graph-order | 教学演示接口，非业务 | 不计入功能需求 |
| 模型 | `deepseek-v4-flash`（旧 `deepseek-chat` 已于 2026/07/24 弃用） | 升级模型名即可，无需改逻辑 |
| 文件输入 | 纯文本（textarea），图片输入为未来扩展（见需求文档 §9） | DeepSeek 托管 API 为 text-only，看图需独立 OCR/视觉组件 |
