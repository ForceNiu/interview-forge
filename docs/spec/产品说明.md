## 产品介绍

### 一句话定位
Interview Forge（面试手记，项目名）是一个**个人面试题库工作台（personal interview question bank workbench）**：帮你把散落的面试知识点收拢成结构化题库，并用 AI（人工智能）基于你的简历（resume）和岗位描述（JD，Job Description）针对性出题、补齐能力盲区。

### 目标用户
正在准备技术面试的开发者（以前端 developer 为主），尤其是：
- 想建立**自己的**面试知识体系、不想依赖零散收藏的人；
- 面具体岗位前想做"能力体检"、搞清楚自己盲区在哪的人。

### 痛点（为什么需要它）
1. **资料散落**：面试知识点散在网页标签、笔记 App、聊天记录里，复习时找不到、不成体系。
2. **题海不对症**：市面刷题是"通用题海"，不针对你**这个人**——会的一直刷、不会的从没被点到。
3. **JD 看不懂自己**：拿到岗位 JD（职位描述）后，不知道自己差在哪、该补哪块。

### 核心价值（3 个）
1. **题库自己掌控**：题目增删改查（CRUD）+ 搜索 + 标签（tag）分类 + 收藏，全本地结构化，浅色 / 深色双主题。
2. **AI 针对性出题**：上传简历 + JD，工作流（workflow）先分析你的能力结构、识别盲区，再按知识域（knowledge domain）并行生成题目；过程中 SSE（Server-Sent Events，服务端推送事件）流式展示进度，出完你**审核后再保存**——AI 是助手不是独裁。
3. **可审核、可追溯**：每道题带难度色块 + 标签，AI 出的题进库前可逐题删除，生成过程留痕（GenerationRun 表），方便复盘。

### 能力全景（一页看完）

| 能力 | 说明 | 详解 |
|------|------|------|
| 题库管理 | 卡片列表 + 300ms 防抖搜索 + 行内删除二次确认 | §1–§4 |
| 收藏 | TanStack Query 乐观更新（optimistic update）收藏列表 | §5 |
| 标签 | 唯一约束 + 引用计数保护（被引用时禁删） | §6 |
| AI 出题 | DeepSeek 工作流 + SSE 流式进度 + 审核保存 | §7 |
| 边界兜底 | loading / error / 404 路由级兜底 UI | §8 |
| 主题 | 奶油赤陶风浅 / 深双主题，刷新无白屏 | 全局说明 |

Next.js 16（React 19）全栈 + Prisma 6 + Neon Postgres + Tailwind v4 + shadcn/ui（手搓 new-york）+ TanStack Query v5 + LangGraph.js 工作流编排。

## 全局说明

- **主题切换**：顶部导航栏右侧"浅色 / 深色"按钮，状态写入 `localStorage.theme`，`<html>.dark` 切换；`layout.tsx` 含防闪白脚本，刷新无白屏。
- **响应式导航**：屏幕 ≤ 768px 时，右上角汉堡按钮打开侧滑菜单。
- **数据库**：Neon Postgres（生产环境 / 本地开发共用同一云库），Prisma 6。
- **路由类型**：
  - 静态预渲染（`○`）：`/`、`/questions/new`、`/tags`、`/favorites`、`/ai-generate`
  - 动态渲染（`ƒ`）：`/questions/[id]`、`/questions/[id]/edit`
  - 含义：新建的题目**不会**立刻出现在首页静态列表里，但会立刻出现在详情页（动态路由）。删除时同理。
- **AI 出题 Key**：DeepSeek API Key 不入数据库，写入加密 Cookie 仅用于浏览器 ↔ 后端调用；可在 `/ai-generate` 页面"更换 Key"。

## 7. AI 出题 `/ai-generate`（真实跑通版）

调用 DeepSeek LLM 出面试题，工作流 = 路由分流 → 并行扇出（按知识域）→ 精炼环。前端 SSE 流式渲染进度 + 审核区。**本章节全部 24 张截图均为真实 DeepSeek 跑通产出**，非 mock。

> 📌 **工作流总览（LangGraph 5 节点有向图）**：`① 分析简历 → ② 路由分流 → ③ 规划策略 → ④ 生成题目 → ⑤ 语义校验`。其中 ⑤ 发现不达标域时回到 ④ **只重出失败域**（精炼闭环，最多 2 轮）。前端经 SSE 流式渲染 5 阶段进度 + 域级细粒度进度 + 题目审核区。

![AI 成功 - 浅色](../screenshots/ai__success__light__real.png)
![AI 成功 - 深色](../screenshots/ai__success__dark__real.png)

- **说明**：全流程跑通，5 阶段全 ✅ + 题目审核区列出全部题目，每题有难度色块 + 标签 + "删除此题"按钮；底部"确认保存 N 道题到题库"。
- **复现**：让真实 DeepSeek 全流程跑通（约 4–5 分钟，含精炼环）。
- **底层事件流**（`phase`）：`analyzeResume` → `routeCandidate` → `planStrategy` → `generateQuestions`（并发 `phase:"domain"`）→ `refine`（可选）→ `done`。

### 7.8.1 取消生成（用户可中途中断）

- **说明**：生成途中点"取消生成"→ 前端 `AbortController.abort()` 触发 `AbortError`，被识别为**用户主动中断（不算失败）**，显示"已取消生成。"轻提示 + "重新生成"按钮，并回到 7.3 的表单填写态。
- **复现**：在 7.7 生成阶段中点"取消生成"（按钮从"开始分析出题"切换为"取消生成"后点击）。

### 7.9 错误态：Key 校验失败（钥匙区提示）

![Key 无效 - 浅色](../screenshots/ai__error-key-invalid__light.png)
![Key 无效 - 深色](../screenshots/ai__error-key-invalid__dark.png)

- **说明**：点"测试连接"后后端校验 Key 失败（401 / 余额不足 / Key 被吊销），Key 输入区下方显示红色"API Key 无效"提示。这是**钥匙区内的局部错误**，不打断页面其它部分。
- **复现**：填入无效 Key 后点"测试连接"。

### 7.10 错误态总览：6 类错误 × 失败节点定位

AI 出题的所有失败被统一翻译成 6 类，前端按 `kind` 做**视觉分化**——同一红横幅但图标与强调不同，让用户一眼区分"到底是哪类问题"；同时横幅副标题显示**失败发生在哪个工作流节点**，进度区对应阶段同步标 ❌。

| kind | 图标 | 横幅标题 | 典型触发 |
|------|------|----------|----------|
| `key` | 🔑 | 密钥无效或权限不足 | Key 错 / 被吊销 / 余额不足 |
| `rate` | 🚦 | 调用频率过高 | DeepSeek 账号级限流（429） |
| `timeout` | ⏱️ | 响应超时 | 模型响应过慢、主动中止 |
| `server` | 🔌 | 服务端暂时异常 | 上游 5xx / 网络抖动 / ECONN |
| `schema` | 📋 | 部分题目格式不合规 | 个别域 JSON 校验不过，已自动跳过 |
| `unknown` | ⚠️ | 生成失败 | 兜底：未分类异常 |

失败节点（`errorPhase`）：`analyzeResume` 分析简历 → `routeCandidate` 路由分流 → `planStrategy` 规划策略 → `generateQuestions` 生成题目 → `validateQuestions` 校验题目。任一节点抛错，红横幅副标题即指明"失败阶段：X"，进度区该阶段从 ⏳/⬜ 变为 ❌。

### 7.11 错误态：致命错误横幅（带失败节点）

![生成失败横幅 - 浅色](../screenshots/ai__error-banner__light.png)
![生成失败横幅 - 深色](../screenshots/ai__error-banner__dark.png)

- **说明**：运行中遇到致命错误（Key 失效 / 超时 / 限流 / 上游抖动 / 未知），顶部红色横幅按 `kind` 显示对应图标 + 标题，副标题"失败阶段：X"指出死在哪个工作流节点，进度区该阶段标 ❌；右侧"重新生成"按钮可一键重试。Key 类（🔑）还会自动展开 Key 输入区引导用户去检查 / 更换 Key。
- **复现**：用无效 Key 直接生成（→ 🔑 密钥无效，失败节点多为生成题目），或制造网络中断（→ 🔌 服务端异常）。

### 7.12 错误态：部分失败（域级，可继续）

![域部分失败 - 浅色](../screenshots/ai__error-partial__light.png)
![域部分失败 - 深色](../screenshots/ai__error-partial__dark.png)

- **说明**：出题阶段个别知识域彻底失败（已重试 3 次），但其它域成功——顶部**琥珀色**提示条列出失败域，流程不中断、已生成的题目仍可审核保存；点"重新生成"只重出失败域。与 7.11 的**红色致命横幅**形成对比：红 = 整体中断，琥珀 = 局部可恢复。
- **复现**：让某个知识域持续调用失败（如该域触发限流），观察琥珀条与已生成题目并存。

`src/app/loading.tsx` / `src/app/error.tsx` / `src/app/not-found.tsx` 是 Next.js App Router 的路由级兜底 UI，捕获 SSR suspense 挂起、客户端错误、未匹配路由三种情况。

### 8.1 加载中（Loading）

![加载中 - 浅色](../screenshots/edge__loading__light.png)
![加载中 - 深色](../screenshots/edge__loading__dark.png)

- **说明**：路由级 Suspense fallback，路由切换或首次进入有延迟的页面时显示（spinner +"加载中…"）。生产环境不会出现，截图通过临时路由人为延迟 2.5s 触发（截完已删除）。
- **真实触发**：访问任意因数据库查询慢、或路由内含 async 组件的页面（在 dev 冷启动首次访问时也常出现）。
- **触发方式**：点导航，但页面有 fetch / await 较慢时。

### 8.2 页面出错（Error Boundary）
